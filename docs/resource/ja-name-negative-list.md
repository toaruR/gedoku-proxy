# 日本語氏名検出（L3'）用 拡張ネガティブリスト仕様書

本ドキュメントは、日本語個人情報（PII）検出システム **L3'** において、「姓（苗字）」の直後に特定の一般名詞や組織名が結合した際、システムがそれを「姓＋名」のフルネームと誤認して確信度（confidence）を `0.90` へ不当に昇格させてしまう問題（例:「佐藤理論」「佐藤体操」など）を防止するための、**拡張ネガティブリスト（除外語彙リスト）**の設計・データセットおよび適用パッチ案です。

---

## 1. カテゴリ別 拡張ネガティブリスト

以下は、苗字の直後に続いた場合に「ファーストネーム」としての昇格を強制的に**拒否**すべき語彙の一覧です。

### ① 学術・科学技術・学説系（「人名 ＋ 概念・法則」の誤認防止）
科学や研究の文脈で、提唱者や発見者の苗字が冠されるケース（「〇〇理論」「〇〇効果」など）を保護します。

*   **理論・モデル**: `理論`, `学説`, `モデル`, `仮説`, `予想`, `パラドックス`
*   **法則・数理**: `法則`, `定理`, `公式`, `方程式`, `関数`, `曲線`, `分布`, `幾何学`, `力学`
*   **現象・データ**: `効果`, `現象`, `プロセス`, `シミュレーション`, `チャート`, `インデックス`, `スケール`, `テスト`, `ライン`, `バリア`

### ② 健康・スポーツ・メソッド・技術系（「人名 ＋ 手法・流派」の誤認防止）
健康法、トレーニング、流派、あるいは特定の技術名称として苗字が使われるケースを排除します。

*   **訓練・実技**: `体操`, `運動`, `メソッド`, `トレーニング`, `ストレッチ`, `ヨガ`, `ダンス`, `ステップ`, `ワーク`
*   **流派・技法**: `式`, `流`, `術`, `法`, `方式`, `技法`, `技術`, `システム`

### ③ 社会・経済・思想・トレンド系（「人名 ＋ 社会現象・制度」の誤認防止）
政治、社会、歴史の文脈で、特定の個人名に由来するトレンド語が一般名詞化しているケースを保護します。

*   **社会概念**: `主義`, `イズム`, `制度`, `世代`, `ブーム`, `ルート`, `ビジョン`, `政策`, `政権`, `内閣`, `改革`, `対策`

### ④ 非法人の組織・施設・ビジネス・医療系（会社名接尾辞の補完）
従来の「電機」「商事」といった株式会社以外の、各種店舗、サロン、医療機関、学術組織などをカバーします。

*   **医療・サロン**: `クリニック`, `医院`, `歯科`, `整形`, `眼科`, `薬局`, `サロン`, `スタジオ`, `スペース`
*   **研究・学術**: `ラボ`, `研究所`, `研究会`, `学会`, `センター`, `オフィス`, `プロジェクト`, `ゼミ`
*   **非営利・公的団体**: `財団`, `社団`, `連盟`, `協会`, `連合`, `機構`, `ファンド`, `ギルド`

### ⑤ 構造的・文脈的ストップワードの補完（名としての誤認が著しい一般語）
日本語の文章構造上、苗字の直後にくっついて一見「名」のようにマッチしてしまいやすい2文字の漢字語です。

*   **機能的接尾辞**: `自身`, `本人`, `周辺`, `以外`, `含む`, `対象`, `担当`, `関係`, `陣営`, `一派`

## 3. 設定ファイル（configs/gedoku.toml）適用パッチ

ネガティブリストをハードコードせず、運用者が自由に追加・変更できるように設定ファイルからロードできるようにする場合の設定拡張スキーマ案です。

```toml
# configs/gedoku.toml

[ja_pii.name]
enabled = true
surname_dict_path = "assets/ja/surname.tsv"
honorifics = ["様", "さん", "氏", "殿", "君", "先生"]

# 拡張: ユーザー定義の追加ネガティブリスト
extra_negative_list = [
  "理論", "学説", "法則", "効果", "体操", "メソッド", "式", "流", "クリニック", "研究所"
]
```

## 4. Rustコード適用パッチ案 (`src/ja_dict/name.rs` 向け)

現在の氏名検出ロジックにこの拡張ネガティブリスト（前方一致判定）を組み込む Rust の実装イメージです。

```rust
// src/ja_dict/name.rs

/// 会社名接尾辞および一般名詞による人名誤認防止ネガティブリスト
const DEFAULT_COMPANY_AND_NOUN_NEGATIVES: &[&str] = &[
    // 従来の会社名
    "電機", "商事", "製作所", "工業", "興業", "商店", "製菓", "自動車", "銀行", "信用金庫", "証券", "不動産",
    // 学術・技術
    "理論", "学説", "モデル", "仮説", "予想", "パラドックス", "法則", "定理", "公式", "方程式",
    "関数", "曲線", "分布", "幾何学", "力学", "効果", "現象", "プロセス", "シミュレーション",
    // メソッド・健康
    "体操", "運動", "メソッド", "トレーニング", "ストレッチ", "ヨガ", "ダンス", "式", "流", "術", "法",
    // 施設・医療・学術
    "クリニック", "医院", "歯科", "眼科", "薬局", "サロン", "スタジオ", "ラボ", "研究所", "研究会", "学会", "センター",
    // 構造的境界語
    "自身", "本人", "周辺", "以外", "含む", "対象", "担当", "関係",
];

/// 検出された「名」候補がネガティブリストに前方一致するか検証する
fn is_negative_word(given_name_candidate: &str, user_extra_negatives: &[String]) -> bool {
    // 1. ユーザー定義の追加リストを検証
    for word in user_extra_negatives {
        if given_name_candidate.starts_with(word) {
            return true;
        }
    }
    
    // 2. デフォルトのネガティブリストを検証
    for word in DEFAULT_COMPANY_AND_NOUN_NEGATIVES {
        if given_name_candidate.starts_with(word) {
            return true;
        }
    }
    
    false
}
```

## 5. 運用のトレードオフと注意点（既知の限界）

本拡張リストを採用するにあたっては、以下の仕様上のトレードオフを理解した上で設計を適用してください。

1.  **「本物の人名」の誤除外（偽陰性のリスク）**
    *   特に「式（しき）」「流（ながれ）」「法（みのり/ほう）」などの語は、非常にまれに実在するファーストネーム（名）として使われる可能性があります。
    *   これらがリストに含まれている場合、実在する「佐藤法（さとう・みのり）」さんというフルネーム表記が出現した際、昇格が拒否され黒塗りされずにスルーされてしまうリスクが僅かに発生します。
2.  **ストップリスト（完全一致）とネガティブリスト（前方一致）の使い分け**
    *   助詞や機能語（「は」「が」「の」等）は、完全に一致する場合のみ人名を遮断する「ストップワード（完全一致）」として扱います。
    *   一方、本リストの「理論」や「クリニック」などは、「佐藤理論物理学」や「佐藤クリニック皮膚科」のように、後ろにさらに別の名詞が続くケースを包含して弾く必要があるため、「ネガティブリスト（前方一致）」として処理するのが適切です。
